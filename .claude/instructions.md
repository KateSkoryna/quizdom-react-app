# Coding Rules

- Avoid unnecessary comments in code
- Code should be self-explanatory through clear variable/function names
- Only add comments for complex logic that truly needs explanation

# Code Quality Standards

Before making any changes, verify that your suggestions meet the following criteria:

- **Best Practices**: Check that all suggestions follow current best practices and modern standards
- **Avoid Outdated Solutions**: Do not use deprecated or legacy approaches; use up-to-date methods
- **Browser Accessibility**: Ensure all features are accessible
  - Follow WCAG guidelines for accessibility compliance
  - Support keyboard navigation
  - Include proper ARIA attributes where needed
  - Ensure screen reader compatibility
- **Design Principles**: Apply fundamental software design principles
  - DRY (Don't Repeat Yourself) - avoid code duplication
  - KISS (Keep It Simple, Stupid) - prefer simple, clear solutions over complex ones
- **Clean Code**: Write clean, accurate, and maintainable code
- **Minimal Comments**: Avoid comments unless the logic is genuinely complex and non-obvious

# Naming Conventions

- Use camelCase for variables, functions, and methods
- Use PascalCase for components, interfaces, and types
- Use UPPER_CASE for constants
- Use lowercase for folder names

# Documentation Rules

- NEVER create README.md or any .md documentation files unless explicitly requested by the user
- Always ask first if documentation files would be helpful before creating them
- NEVER add your description to commits, only commit message should be provided
